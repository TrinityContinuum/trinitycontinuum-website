# Trinity inquiry API (not deployed)
Requires dedicated PostgreSQL, restricted administrator token (32+ characters), transactional SMTP credentials and verified sender alignment. Set DATABASE_URL, ADMIN_TOKEN, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, MAIL_FROM, PUBLIC_ORIGIN. Run schema.sql before starting. Never commit .env or customer records. Render service root directory intake-api, build npm install, start npm start. Production release requires managed TLS, approved costs, privacy/retention policy, anti-bot controls, reliable queue/worker, alerting, separate acknowledgment/notification retry state, export and authenticated admin UX. This is a backend foundation, NOT production-ready: asynchronous email after HTTP response may be interrupted by instance restart, retries can duplicate notifications, no durable queue or failure alerts. No live mail delivery verified.
